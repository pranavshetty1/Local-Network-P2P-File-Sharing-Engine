# Local Network P2P File Sharing Engine

A Java-based console simulator that demonstrates peer-to-peer file sharing over localhost using Java TCP sockets.

> **Important:** This project is a simulation/demo of a local network P2P environment. It creates three virtual peers on `127.0.0.1` using different TCP ports. It is not intended to represent a production-ready LAN file-sharing system.

## Features

- Three virtual peers:
  - PC-Alpha — `127.0.0.1:9001`
  - PC-Bravo — `127.0.0.1:9002`
  - PC-Charlie — `127.0.0.1:9003`
- Each peer has its own simulated shared folder.
- Each peer runs a Java `ServerSocket`.
- Peers communicate using TCP sockets.
- List files available on a peer.
- Download/copy files from one simulated peer to another.
- Add new simulated files.
- Handles missing-file requests.
- Supports files of different sizes and common file types.
- Console-based interface.

## How It Works

The application starts three virtual peers. Each peer:

1. Has a unique name and localhost port.
2. Maintains a local directory containing its simulated files.
3. Starts a background `ServerSocket`.
4. Accepts `LIST` and `GET` requests from other peers.

For example:

```text
PC-Alpha (9001)
      |
      | GET|report.pdf
      v
PC-Bravo (9002)
      |
      | file bytes
      v
PC-Alpha
```

The application uses real TCP socket communication, but all peers run on the same computer using `127.0.0.1`.

## Default Files

| Peer | Port | Initial Files |
|---|---:|---|
| PC-Alpha | 9001 | `notes.txt` (4 KB), `photo.jpg` (300 KB) |
| PC-Bravo | 9002 | `report.pdf` (150 KB), `backup.zip` (2000 KB) |
| PC-Charlie | 9003 | `movie.mp4` (5000 KB), `resume.docx` (40 KB) |

File sizes shown above are the sizes generated by the program.

## Compile

Open a terminal in the project directory:

```bash
javac P2PConsoleSimulator.java
```

If compilation succeeds, a `P2PConsoleSimulator.class` file and additional inner-class `.class` files will be created.

## Run

```bash
java P2PConsoleSimulator
```

You should see output similar to:


## Available Commands

### 1. Show all peers

```text
peers
```

### 2. List files on a peer

```text
list 1
```

Example:

```text
-> PC-Alpha: LIST
PC-Alpha -> : notes.txt|4096
PC-Alpha -> : photo.jpg|307200
PC-Alpha -> : END
```

### 3. Transfer a file

The command format is:

```text
get <from#> <to#> <file>
```

Example:

```text
get 1 2 report.pdf
```

This means PC-Alpha requests `report.pdf` from PC-Bravo.

Expected output is similar to:

```text
PC-Alpha -> PC-Bravo: GET|report.pdf
PC-Bravo -> PC-Alpha: SIZE|153600
PC-Alpha: received 153600 bytes in <time> ms
```

### 4. Add a simulated file

Format:

```text
addfile <#> <name> <kb>
```

Example:

```text
addfile 3 demo.txt 2
```

Expected output:

```text
Added demo.txt (2 KB)
```

### 5. Exit

```text
exit
```

## Suggested Demo

For a college/project demonstration, run:

```text
peers
list 2
get 1 2 report.pdf
list 1
get 2 1 missing.txt
addfile 3 demo.txt 2

```

This demonstrates peer discovery/display, file listing, successful file transfer, missing-file handling, adding a file, and listing again.

## Technical Details

The project uses:

- `ServerSocket` for each virtual peer's server.
- `Socket` for peer-to-peer communication.
- `LIST` requests to retrieve available files.
- `GET|<filename>` requests to transfer a file.
- `SIZE|<bytes>` to communicate the requested file size.
- `END` to mark the end of a file-list response.
- Java file I/O for creating, reading, and writing files.
- Background daemon threads to allow peers to handle socket requests.

## Limitations

This is a learning/demo project rather than a production P2P engine.

Current limitations include:

- All peers run on the same machine.
- Peers use `127.0.0.1` instead of separate LAN IP addresses.
- No automatic peer discovery.
- No authentication or authorization.
- No encryption.
- No cryptographic file-integrity verification.
- No download resume mechanism.
- No GUI.
- No persistent peer registry.
- The temporary peer directories can retain files between program runs because the program seeds initial files only when a peer directory is empty.
